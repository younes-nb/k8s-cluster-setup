## Deployment safety

- Stop every scale writer and active experiment before applying the benchmark role; explicitly set `LAB_EXCLUSIVE_WRITER_CONFIRMED=true` only after inspection. The role will reconcile upstream replicas; do not rerun it mid-experiment. No automatic HPA; use the same 46-service allowlist for native HPA and controller scale-write RBAC. RabbitMQ and databases are not scaling targets.
- Use the exact pinned checkout and rendered manifests. Supply stable DB credentials in encrypted `zz-local.yaml`; use the existing DB Secret values if reconciling a running cluster. Never log passwords, change them implicitly, delete DB PVCs, or recreate a StatefulSet to bypass an immutable-field error. For existing timestamped claim names the patch retains the exact claim template and storage size; fresh deployments use `mysqldata`. If an existing primary has a missing/unbound claim or orphaned claims, stop and investigate. If an older Nacos StatefulSet uses OrderedReady, the new Parallel policy is immutable; plan and validate a deliberate maintenance operation for Nacos only (after backup and inspection) or preserve existing policy with a verified non-quorum readiness strategy. Do not force Helm replacement or alter the MySQL data. Verify the pinned initmysql image's schema initialization is idempotent/concurrency-safe before using Parallel on a fresh cluster; if not, run one version-pinned initialization Job before starting members, and encode that in source.
- Preserve upstream application resources, images and JVM environment. Verify live resources vs pinned manifest and resolved image digests. The shared `ts` schema and two standalone MySQL primaries are deliberate benchmark modifications; document schema compatibility, seed state, per-service connection pools, binary log growth and data persistence. Test MySQL 8.4 separately, not during the comparison. The 520-pod object ceiling accommodates 460 application pods plus infrastructure and some surge; verify actual node capacity and headroom, and document a global budget if lower.
- Verify readiness for every container, Nacos and RabbitMQ. Populate local `tt_probe_overrides` and `tt_infra_probe_overrides`. The original 45 TCP probes and missing UI probe are not sufficient evidence of serving readiness. `/welcome` handlers are candidates for connector readiness only, not semantic proof. Verify actual image endpoints and tools, initialization state, Nacos registrations, endpoint discovery and first successful request per new replica. Do not add probes that cascade on all downstream failures or liveness that kills overloaded apps.
- No application NodePort, including Nacos; use Gateway API, Envoy Gateway and private MetalLB VIP. Retain internal Kubespray API proxy. Do not add a service mesh, monitoring profiles or external API load balancer.

## Local metrics TLS gate

Scheduler and controller-manager bind to 127.0.0.1 on each master. The patched node Alloy scrapes HTTPS 10259 and 10257 with ServiceAccount authentication and a verified trust bundle. The unreachable ServiceMonitors are disabled. Before `--tags alloy`, configure stable serving certs with correct loopback SAN and authorization via supported Kubespray/kubeadm settings, validate CA and actual leaf, and provision PUBLIC trust bundles at `/etc/kubernetes/metrics-ca/scheduler.crt` and `/etc/kubernetes/metrics-ca/controller_manager.crt` (master-specific as necessary). Put valid public bundles also on workers so Alloy can load TLS config even with zero local targets. Encode certificate setup in Ansible, protect keys outside the collector mount, do not copy cluster admin key or blanket approve CSRs. Check renewal/reboot. Do not disable TLS verification, expose the ports publicly or replace with fake metrics. The patch contains a fail-closed presence gate, not a verified certificate issuance implementation. If pinned components require different stable names or SANs, adapt declaratively and test.

## Load-testing evidence from upstream source

- `ts-ui-dashboard/nginx.conf` proxies `/api/v1/` to `ts-gateway-service:18888`. The application gateway routes via Nacos (see `ts-gateway-service/src/main/resources/application.yml`). Validate the complete VIP -> Envoy -> UI -> application gateway -> service path. Measure both gateway and frontend constraints; the UI has one nginx worker/1024 worker connections. Do not bypass the gateway to make results look better.
- `gateway/GatewayConfiguration.java` installs a Sentinel flow rule of 20 QPS for **only** route `admin-basic-info`. Its startup message sounds global, but the rule is route-specific. Confirm behavior against actual image; distinguish deliberate admission/rate-limit rejections from saturation. Do not remove the rule without documenting benchmark change and applying it to every baseline.
- `ts-common/.../util/Response.java` defines status 1/0, msg, data. `PreserveController.preserve` returns HTTP 200 with a Response; `PreserveServiceImpl` can return `Seat Not Enough` (business rejection, not evidence of CPU capacity). `auth/controller/UserController.java` returns HTTP 200 for get-token errors. `travel/controller/TravelController.java` can return HTTP 200 and an empty array for invalid trip input. Parse each API by its actual contract, not a universal HTTP status or JSON-shape assumption.
- `/api/v1/stationservice/stations` returns `Response` with a successful nonempty list or status 0 `No content`. The added `api-smoke.js` checks actual seeded read-only API success. It is not a representative workload and is not a substitute for authentication, search, preserve, pay, cancel or other actual workload flows. Run distinct IDs for UI and API smoke; `source /opt/loadgen/k6.env`, `export EXPERIMENT_ID=$(cat /proc/sys/kernel/random/uuid)`, then `k6 run -o experimental-prometheus-rw /opt/loadgen/api-smoke.js`. Confirm actual metric names, timing units and expected counters; the API smoke measures wall time for its good/slow outcome (unlike the UI smoke's HTTP request-duration boundary).
- Inspect the real research load scripts, CSV, user pool, seed and time compression. Distinguish scheduled iterations, started HTTP attempts, terminal success/slow/failure, in-flight/interrupted/unknown, and dropped iterations. Failure subtypes are subsets, not additional outcomes. Reconcile counts after drain, identify missing samples and counter resets; a negative difference must surface as invalid accounting, not be clamped to zero. Never count a token reuse, preflight, or retry as a completed business transaction. Use unique run IDs, route/operation labels of controlled cardinality, raw result archives and explicit experiment bounds. Separate client wall latency, HTTP duration, server P90 and transaction duration. No blind retries on mutating operations.

## Acceptance gates

1. Run `python3 tests/static_validate.py`, `python3 -m unittest discover -s tests -p 'test*.py'`, `python3 tests/test_pinned_quickstart.py --train-ticket /path/to/pinned/train-ticket`, actual Ansible syntax checks, Helm lint/template on patched charts and Kubernetes schema/server-side dry runs. Validate passwords only with synthetic fixtures in logs. The integration test's TCP probes are synthetic fixtures only.
2. On the live cluster verify all StatefulSet claims and credentials remain unchanged after a safe rerun (save UID, PV UID, mounted device and sentinel row before/after); verify Nacos three-member health and RabbitMQ connectivity. Run full workflow smoke, including seeded business outcomes and failure cases.
3. Both MySQL exporters required (`nacosdb-mysql`, `ts-mysql`). Provision least-privilege accounts declaratively and monitor MySQL threads, rejected connections, locks, buffer pool, disk and actual queries. Add Nacos registered-instance/discovery metrics and RabbitMQ queue and delivery metrics appropriate to pinned versions. Do not invent metric names or silently disable unavailable features. Test database bottlenecks separately from scalable service bottlenecks.
4. Validate all eight host exporters, six kubelets, three local control-plane scrapes, three Beyla agents, three profiling agents, six Alloy node agents and all backends. Ensure raw input freshness <=15s for online features and measure actual ingestion lag, exporter resets, histogram units and boundaries, namespace and unique producer identity before aggregation, OTLP temporality, trace completeness, profile retrieval, and overhead. Correct namespace labels using actual Beyla output (`client_namespace` vs `client_service_namespace` etc.) in rule, dashboards and validator together; verify every expected active edge independently, not merely whichever edges exist. Use namespace-scoped identities, and validate missing/stale/duplicate series as failures. Native histogram query candidates use `k6_http_req_duration_seconds`, verify actual exported name.
5. SLO: PBScaler detection uses edge P90 >220 ms for Train Ticket (200 ms * 1.1); evaluation uses application P90 >200 ms. Measure valid and missing 15s observations over exact run bounds, record frontend and independent client measurements, include failed/aborted requests in separate outcome metrics. Never equate interval violations to percent of failed requests. Do not turn missing into zero. Confirm client and server histogram semantics and reproduce PBScaler's original observation window before comparing. Keep k6 as independent evaluation, not a required controller input.
6. Inspect every provisioned dashboard panel with appropriate stimulus; report unsupported metrics explicitly. Add Nacos/RabbitMQ and query/lock metrics with real names, outcome categories, in-flight and missing telemetry, gateway failure and saturation, and profiling/trace health. Ensure unique experiment selection and correct units. Do not fabricate metrics for a future controller.
7. Verify resource/placement, no competing controllers, quota/headroom, one controlled scale-out/scale-in of a stateless target and first serving request. Separate pending admission, scheduling, Running, Ready, Nacos registration, serving, termination. Stop and restore baseline between runs; record exact code/images/workload seed and run identifiers. Measure instrumentation overhead and total telemetry/query cost relative to the 15-second decision interval; future model inference cannot yet be validated.
8. Persist source corrections, evidence (redacted), static and live logs, image digests, manifest checksums, reproducible run commands and unresolved limitations. Do not declare research-ready until mandatory gates pass. If the separate project chat is accessible to the deployment agent, read it before modifying workload code and reconcile its findings with source and current runtime evidence.
