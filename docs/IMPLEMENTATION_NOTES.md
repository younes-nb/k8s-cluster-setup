# Implementation notes and residual validation work

The new CloudLab cluster replaces the previous one. Removed the legacy migration workflow and stale controller patching; do not merge those files back. The merged source includes all actual text files; compiled bytecode is intentionally excluded. Latest supplied versions are retained except for explicitly pinned direct Python packages and the local-path helper image. Confirm these resolve; pin image digests and lock transitives during runtime verification.

Implemented: staged orchestration, strict argument validation, dedicated control-plane placement, safe disk identification/format guard, monitoring mount and firewall, private bindings and Grafana secret, distributed Alloy and profiling, Beyla features/frequency, explicit DB exporter wiring, Mimir rules, Tempo/Pyroscope retention candidates, monitoring of control plane and etcd, datasource UIDs, SLO and other dashboard replacements, gateway tracing, VIP validation, database PVC mounting, quota compatibility, fail-closed probes, scoped controller RBAC, k6 smoke/remote-write environment, strict metrics acceptance and negative tests. Preserved upstream resource requests/limits/JVM settings. No alternate monitoring modes, no Istio, no NodePort application path, no external API LB.

Runtime-specific gaps: exact release probes (strictly required but not guessed), DB exporter account provisioning (explicit credentials and connection mappings required), kubelet serving certificate verification/approval, actual supported Beyla runtime and protocol signals, exact series labels and Grafana panel queries, Tempo 3/Pyroscope/Mimir and Alloy version compatibility, gateway EndpointSlice tracing integration, security of private LAN and deployment topology, and complete business-level request accounting (external research scripts absent). The source changes are a candidate, not a proof of readiness. The agent must fix runtime incompatibilities in source, not remove safety gates. DB exporter readiness is not guaranteed merely by providing one DSN; confirm every datastore. All old dashboards were inspected and obsolete Istio queries replaced. 11 provisioned dashboards include diagnostic panels requiring actual data. Existing monitoring does not provide the proposed autoscaler model or causal classification algorithm.

The design uses a private monitoring network without application-layer TLS on ingestion, protected by interface bindings and a host firewall; this is a deliberate research-lab simplification. Add TLS/auth where traffic is not trusted. Exact certificate and monitor configs still require cluster validation. Explicit manual authorization is required to format a disk. No attempt to preserve previous cluster data is needed, but never destroy data on a machine without validating its identity and use.
