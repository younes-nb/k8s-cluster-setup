# Monitoring completion and safe certificate reconciliation

Target: current CloudLab installation, repository base c1a8594. Do not rebuild it, delete PVCs, rotate DB credentials, or start a second autoscaler. Run during a maintenance window, not an active experiment. This patch is offline-tested, not live validated. Keep all runtime corrections declarative.

## Control-plane serving PKI

The retired shell helper is intentionally non-executable in practice (exits with an error). It created fresh CA keys every run and put backup manifests in kubelet's watched directory. Do not run old copies. Inspect all three masters for `kube-scheduler.yaml.bak`, `kube-controller-manager.yaml.bak`, and other non-active manifests. Preserve known backups outside `/etc/kubernetes/manifests`. Move known legacy backups one master at a time and check control-plane health. Do not delete unknown files.

`postcluster.yaml --tags metrics-certs` now invokes `metrics_certs.yaml`; the normal role and `--tags alloy` also include it. Use the project's documented inventory, vault and kubeconfig invocation. The helper executes on each master via inventory delegation, with API and mirror Pod health checks around each master. It validates the two existing TLS flags, root-owned/read-only PKI mount, delegated authentication flags and expected serving certificate on localhost. Existing valid legacy cert/key/public CA files are adopted without rotation, even if the old signing CA key was lost. Known `.yaml.bak` files are preserved under `/etc/kubernetes/backup/metrics-manifests`. For fresh hosts with no managed PKI artifacts, it generates an individual local CA (key under `/etc/kubernetes/metrics-signing`, root-only) and leaf certificates with loopback SAN; only public trust is copied to workers. Each master's collector uses that master's own CA. No signing key is copied to workers or the controller. A new leaf is not generated on every run. Expiring, partial, mismatched or conflicting existing PKI fails closed; implement an explicit maintenance/rotation procedure with verified trust transition, not automatic replacement. If the legacy signing key really is gone, a future controlled CA replacement is unavoidable before expiry.

The helper assumes the current kubeadm/Kubespray layout: root-run components, explicit command lists, existing delegated authentication and authorization kubeconfigs, and a read-only matching host PKI mount. Inspect the real manifests BEFORE running it. If different, adapt the source to actual pinned Kubespray conventions, preserving all unrelated flags and security settings. Do not bypass these checks. If a changed manifest fails TLS handshake, the helper restores that manifest; check actual Pod recovery and cluster health before retrying. A stopped run can leave generated but valid PKI files on disk; they are intentionally not removed on rerun. The certificate handshake checks TLS, not HTTP authentication. No live Kubernetes tests were performed by the patch author.

Diagnose each metrics endpoint with the Alloy node ServiceAccount projected token and its local public CA (no token output). Confirm `--authentication-kubeconfig`, `--authorization-kubeconfig`, TokenReview and SubjectAccessReview authorization, API reachability, audience/expiry and RBAC `GET /metrics`. Distinguish certificate errors, 401, 403 and connection failures. Use a dedicated least-privilege client cert ONLY if necessary and explicitly provision and renew it; never use an admin key, insecure TLS or anonymous metrics. After successful reconciliation run Alloy config validation, test actual endpoint and inspect Mimir `up` for all three masters per job. A TLS handshake alone is not a pass. Re-run twice, compare certificate fingerprints and manifest hashes, and verify no unexpected changes. Confirm persistence across Kubespray upgrade/reconciliation and reboot; if Kubespray owns/replaces flags, wire the verified settings into its supported configuration as needed.
